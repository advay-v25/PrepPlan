## Changes

- **Phase 0 Auth.** Sign-in after reset could submit the static HTML form before React attached its handler. The browser requested `GET /login?` and returned to sign-in without calling the auth API. Sign-in, sign-up, resend, reset request and password-update controls now become available when their client handlers are ready, in addition to their existing checks. The regression drives confirmation, reset, password sign-in and the full onboarding flow on local Auth.
- **Phase 1 Log.** An unavailable reading search keeps the query and offers Retry. A successful search with no matches still has its own empty state. The browser check deliberately fails the scoped search once, retries, chooses the exact reading and verifies that the separate session leaves the original study block untouched.
- **Phase 1 → 3 visibility.** Tests can show the confirmed readings for this week even when the blueprint cannot yet produce a paper. Those links describe recorded coverage. They do not make an assessment startable or create evidence.
- **Phase 2 fixture.** The keyboard and IME test opens the explicit agenda before selecting a class. The test presses Enter on the focused class control, then checks Tab confinement and Escape. This avoids testing a week-grid control that mobile may replace during automatic view selection. Class recovery itself uses the existing migration through `20270209`.
- **Phase 1 → 3 frozen paper.** The scored browser suite now logs a new reading through the UI after reservation. The live scope revision changes. Resuming the same attempt retains its form ID, item order and versions, frozen scope, deadline and scoring policy. The suite then scores the original paper, whose result leads to reviewed repairs, Calendar work and a newly eligible spaced re-check.
- **Phase 3 rehearsal.** The existing linked-rehearsal HTTP journey can use the explicitly selected local-stack mode. It runs the same loopback readiness check as browser fixtures. The hosted disposable-project check is preserved for other modes.
- **Local entry and cross-page regression setup.** Auth browser fixtures use the existing target-host guard, including its explicit local mode. The entry HTTP script passes the expected setup version and checks that the saved uncertainty and mock survive. The Home/Tests browser test checks the current reading summary on Home and exact outcome counts through the signals contract; a whole outcome does not necessarily make the full reading covered.
- **Lifecycle regression setup.** Journey A now changes one of two outcomes on a separate log, observes a new scope revision and waits for the explicit stale-start HTTP 409 before checking that no form or attempt was written. Its old fixture could submit an unchanged scope and count the generic route alert as refusal. Journey B uses the current class setup disclosure label.
