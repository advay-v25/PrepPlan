**Implementation status.** The entry fixes below are in the working tree. Recovery includes flow-specific actions for missing, malformed and expired links, in-place security-check retry and a signed reset receipt. Public sign-in, signup, reset request, email resend, link failure and the anonymous setup redirect were captured on PrepPlan at 1280 × 900 and 390 × 844. The largest usability problems are recovery actions that fail to identify the next step, settings for class-led and mature entries that are too easy to miss, and mobile setup that hides important details below a sticky action. Keep the brand, clear labels, explicit setup acceptance and optional detail. Simplify the task a student has to do on each screen.

## Backend architecture · keep the website light

Use the existing Next.js server and Supabase/Postgres as the application backend. This is mainly a change to what each screen reads, what each command owns, and when expensive work runs. Keep interactive UI in the browser and make it consume narrow, typed screen data. Retain the current routes and transactional commands where they already own a write correctly.

| Boundary | What it owns | What the browser receives |
|---|---|---|
| Next.js Server Components and small client islands | Read the viewer and requested screen once. Render the useful first view on the server. Load drag, charts, editors or animations only where used. | The selected screen’s data and interactive controls. A loader, failure and retry can render independently of other sections. |
| Server-only services | Assemble a week, validate contiguous fit, load policy and catalogue details, compute evidence, score and prepare a Coach proposal. Share decisions and scope semantics across pages. | A plan preview with a revision, a result summary, or a proposal with specific actions and links. |
| Postgres and existing commands | Owner checks and access guards, idempotency, version checks, frozen forms, transactional updates for tasks, receipts and accepted drafts. Index exact read patterns based on traces. | A safe error code and next step on refusal. A receipt and affected record IDs on success. |
| Private reference and question stores | Versioned, authorised reference packs, source provenance, question families, keys, scoring and draft authoring. Store permitted reference files privately and link their versions to manifests. Load only the relevant section in back-office work. | Public or permitted catalogue labels where needed, one reserved question without its key until the result policy allows disclosure, plus a safe result breakdown. |
| Bounded background work | Bulk authoring, evaluation and optional notification dispatch. Reuse existing batch and reminder workers, with explicit budgets, deduplication, deadlines and retry status. Move interactive projections to an asynchronous job only if measured latency warrants it. | Persisted progress and an honest retry. Planning, manual logging and account entry must remain usable when a model is unavailable. |

### First backend changes

1. **Measure first.** Reuse request tracing and stage timers on the production build. Record request count, database round trips, query and route time, HTML/RSC bytes and client JS per route. Measure cold and warm requests, desktop and a mid-range phone profile, with ordinary and long-history accounts. Record errors and tail latency. Keep secrets, private source passages, notes, answers and raw auth identifiers out of logs.
2. **Split onboarding reads by step.** The page currently loads exam windows, all topics and active module names for every step. The canonical loader makes six reads, several with full row selects. Keep the small progress and current setup summary in the shell. Exam gets eligible month labels, Study style gets class details, Starting point gets topic labels and fetches reading options when expanded, Your week gets current windows and commitments, Review gets the compact draft. Preserve existing server validation, incomplete-user routing, optimistic version checks and exact return links. Replace unused columns before changing storage.
3. **Make logging fast at its entry point.** The quick log currently fetches topics, active readings and every outcome, plus timezone, on open. For a known planned task, load only its title, outstanding work and scope. For an unplanned session, start with recent readings and use paginated search plus one reading’s outcomes. For a class, read the selected occurrence and its scope. Keep existing compatibility while migrating clients. Return one compact receipt from the write. Home and Calendar should refresh the affected section from canonical truth.
4. **Read planning inputs once and write once.** Assemble the cycle, intervals, accepted occupancy, current coverage, obligations and assessment constraints on the server. Pass a typed snapshot into the deterministic planner. Return fit, reasons, waiting work and a draft revision. At accept time recheck ownership, scope, date and fit under the existing locking pattern and write changes with one receipt. A provider response cannot change the schedule itself.
5. **Keep Home, Tests and Coach focused.** Home initially needs the next action, today’s short list and key warnings. Fetch evidence history and roadmap detail when requested. Tests needs a capability decision and a reserved question, then results. Coach uses existing scoped views and the exact task/proposal context. Keep write-authoritative reads current. Share request-local results first. Cache only static permitted curriculum labels by manifest/version and consider incremental per-student summaries only when traces justify the invalidation complexity.
6. **Preserve private boundaries.** Keep all storage private by default. Maintain app access and row ownership before lookup or write, role checks for reviewer work and size, latency and rate bounds for provider routes. Use original or authorised assessment inputs. Keep user notes separate from the reference corpus, send only opted-in selected text for drafting, and keep the product without a student upload flow. Audit generated client assets, server-rendered payloads and API responses for private fields. Use the existing verified diagnostic pipeline and exact-version approval. Archive or purge according to account policy.

## Phase 1 · Log a session and see what changed

1. Open capture with the selected Calendar task when present. Otherwise offer explicit open-block choices and a separate session. Never match solely by a title or date. Keep the occurrence-specific route for scheduled classes.
2. Record minutes, completion, scope and history in one owned command for a planned block. A separate session creates one activity. Reuse existing commands where possible. Same request and key replay the receipt; meaningful edits to the payload require a new operation. Preserve input on errors and reconcile any unknown save.
3. Defer catalogue reads until the student needs to pick a reading or outcomes. Bound reads and saves. Time-only logs should still show on Calendar and Home with a path to confirm coverage. Confirmed scope drives new papers; an opened paper remains frozen. Partial class material stays pending until explicitly confirmed.
4. Reflect the same receipt on Home, Calendar, Curriculum, Tests and Coach. Offer follow-up through a reviewable draft, and say when an earlier log went to history. Preserve accepted work and be explicit when a current-week change requires review.
5. **Acceptance.** From a 45-minute task, log 25 minutes and one confirmed outcome, then reload. Calendar has one task/event and 25 minutes. Carry the unfinished work once and finish it next week without changing the old week’s history. Repeat with a separate session, a late log, same-day classes, lost response, two tabs and scope changed after reservation.

## Phase 2 · Make the Calendar constraint-aware from first pass to exam

1. **Shared fit.** Start with study intervals on the student's local date. Clip elapsed time and subtract classes, work, exceptions, accepted timed work and mocks. Pack flexible tasks against actual gaps and show their flexible status. Two 30-minute gaps can fit two 30-minute sittings. A 45-minute unsplit sitting waits. Apply max sitting, prerequisites and segment order. Validate the same rules on draft acceptance under the scheduling lock. Deliberate personal overrides retain the single warning and protected conflicts still fail.
2. **First pass.** Track remaining work by scoped reading or ordered segment. Split larger portions across gaps and weeks, keep the debt visible, and avoid labelling portions complete from planned minutes alone. Midway entrants start from remaining work and separately flagged uncertainty. For class-led students, actual upcoming classes define the boundary, with the test before the next class when feasible. Self-study runs Monday to Saturday with the weekly paper on Sunday. If no suitable assessment slot exists, show the scheduling choice and a closure path.
3. **Weakness-only bridge.** Enter when the first pass is recorded complete or the entrant reports completion. Before broad revision begins, assign evidenced misses and unstable concepts, with optional agreed checks for self-reported uncertainty where the bank supports it. No recorded evidence does not imply weakness. If there are no justified repairs, leave room open or offer earlier planned revision. Keep routine rotation for general revision.
4. **Revision and final prep.** Schedule spaced cumulative coverage in the revision phase. Protect the planned mock and final preparation window, normally up to eight weeks as the horizon allows. If first pass is still incomplete at that boundary, show choices about scope and timing rather than secretly filling mock weeks with first-pass tasks. Reserve mock time, debrief and feasible repairs. A mature February entrant with a poor mock should get a short weakness plan around existing commitments and the next feasible checkpoint.
5. **Deviations.** Reconcile when weekly review is accepted, coverage changes, a class moves, availability changes, the exam date changes, or mock evidence arrives. Propose bounded changes and show the reason. Accepted and historical work is preserved except for explicitly confirmed edits. Offer a valid empty week if there is no room.
6. **Acceptance.** Fresh, midway and late-entry plans must hold with fragmented free time, elapsed windows, protected appointments, midnight, DST, adjacent bookings and no capacity. Prove the same invariant for generated drafts, acceptance, recovery and assessment. Test short class transitions, stable segment order and a moved mock. A midweek exam test must include real work, inventory and free windows after the cutoff so it cannot pass with an empty plan.
