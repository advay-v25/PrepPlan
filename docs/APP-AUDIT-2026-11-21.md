# Roadmap application audit — 21 November 2026

The [audit follow-up](APP-AUDIT-FIXES-2026-11-21.md) records the current fixes, cleanup decisions and verification.

Scope: the whole application, read without reference to phases or plans. Method: static scans of all of `src/` (pages, 79 API routes, 106 components, 208 lib modules), a live crawl of 88 page views (anonymous, self-study and class-led students; desktop 1280 and phone 390), a click-through of the visible buttons on 12 pages, screenshots of 8 pages at both widths, and targeted code reading where a scan pointed. Test users were owned throwaways and were deleted.

## Read this first: limits of this audit

1. **The working tree was changing under the audit.** `npx tsc --noEmit` currently fails in the auth area (`src/app/auth/callback/route.ts`, `src/app/auth/verify/page.tsx`, `src/app/login/page.tsx`: `redirectType`, `VerificationForm`, `nextPath` do not exist yet), `src/app/auth/verify` is new, and the sign-in confirmation link now redirects to `/auth/error?reason=invalid`. In that state every protected route returned 500 to an anonymous visitor in dev (`Invalid URL` from the proxy redirect). I treat that as unfinished auth work, **not** as a confirmed product bug, and I did not audit sign-up, login, reset or verification behaviour. Re-run the crawl once that work lands (item A-01).
2. Timings were taken on the dev server (cold compile included). They are only used to pick what to measure in a production build.
3. My button click-through used accessible-name matching that failed on long labels, so it proves little about individual buttons. Interactive claims below come from code reading, not that run.
4. Not re-audited in depth because earlier phases carry their own proofs: planner correctness (`generateWeek`), reminder delivery, ICS output, the reviewer workflow internals, bank/LLM pipeline. They are listed under "Needs a deeper pass".

Severity: **P0** blocks beta, **P1** wrong or misleading behaviour a student will meet, **P2** quality or maintainability, **P3** polish.

## C. Bloat, dead code and duplication
1. **Dead code that also contradicts product rules.** `src/lib/state/readiness.ts` `computeReadiness` blends coverage (60%) and diagnostics (40%) into one number. Nothing in the app uses it (only `scripts/readiness-test.ts`), and the house rule is "never one blended score". Delete it and its test.
2. **Unimported modules** (only scripts/tests reach them): `curriculum/catalogue.ts`, `diagnostic/adversarialCases.ts`, `planning/repairDates.ts`, `tests/bankCoverage.ts`, `lib/testing/e2eIdentity.ts` (and `state/readiness.ts`). Decide per file: move to `scripts/lib` or delete with its test.
3. **86 exports referenced nowhere else** (e.g. `splitTask`, `commitWeekPlan`, `observedMinutesPerEffortUnitFrom`, `listRehearsals`, `isAppRoute`, `isOnboardingRoute`, `staggerIn`, `fadeInUp`, `redactForLog`, `coachAttemptHref`). Remove after a grep of scripts.
4. **Copy-pasted helpers.** A date formatter (`new Intl.DateTimeFormat('en-GB', …)`) is redefined in at least 10 files; `timeLabel` in 3; `realDate`/`isRealDate` in 4. 47 hard-coded `'en-GB'` uses in 38 files. Create `lib/format/date.ts` (one locale decision) and import it.
5. **CSS.** One 2,252-line `styles.css`; about 227 of 973 class names are not referenced anywhere in `src` (e.g. `dashboard-*`, `diagnostic-*`, `day-block*`, `calendar-block*`, `coverage-node*`). Remove after checking dynamic class construction.
6. **Duplicated task mapping** in `classlog/service.ts` (`confirmClassLog` and `confirmClassLogUpdate` build the same task payload). Extract one function.
7. **Oversized files** worth splitting once stable: `roadmap.ts` (706 lines), `classlog/service.ts` (684), `diagnostic/verifier.ts` (665), `generateWeek.ts` (613), `CalendarWeekGrid.tsx` (535). `as any` appears 186 times; type the API response shapes used by client components first.
8. **Legacy routes kept as redirects** (`/app/syllabus`, `/app/week`, `/check/result`) have no inbound links; keep only if external bookmarks matter, otherwise remove with their `.bak` reference.
9. **Repository clutter.** `closed-week-390.png` in the repo root; leftover build folders `.next-build`, `.next-curriculum-audit`, `.next-lifecycle`, `.next-p1`, `.next-p4`, `.next-p5`, `.next-phase6-owner-review`, `.next-repair-coach`, `.next-settings`; 74 files in `docs/`, many of them agent prompts. Archive or delete (owner's call). My audit scripts are in `scripts/_audit/` and can be deleted.

## D. Enhancements (not bugs)
1. Home: one explicit "what changed since you were last here" line; today it is a stack of notices.
2. A single "Log learning" entry that remembers the last reading and extent (the sheet has many steps for a repeat action).
3. Calendar: keyboard shortcut and visible hint for "move"; agenda-first on phone (it already switches at 760px).
4. Tests: show the reason a paper is unavailable in one sentence with one action, instead of two cards.
5. Settings: group "Exam", "How you study", "Where you are" with a summary of what a change will invalidate before the student presses Change.
6. Error pages: every "could not load" state should carry a Retry action and a request id the student can quote to support.
7. Localisation: format dates and times from the student's locale, not `en-GB`.
8. Add `aria-live` regions for save states ("Saved") that are currently visual only.
